Network Troubleshooting Lab

Configure two routed /24 subnets with two switches, two clients and a DNS server. Compare connectivity with an incorrect default gateway, then isolate a DNS error while direct IP access still works.

R1 routes between the subnets. DNS-S resolves lab-host.local to 192.168.20.10 in this proposed Packet Tracer exercise.

02 · Facilitator plan · Delivery not yet recorded

IT Technical Training Pilot

Turn the network lab into a two-session, performance-based learning experience. Start with independent diagnosis, model and practise a structured method, then assess a different fault without assistance.

  1. Baseline: note how learners select initial checks.
  2. Session 1: instructor models the gateway and DNS troubleshooting cycle with guided practice.
  3. Session 2: learner fixes an unfamiliar fault, captures proof and receives targeted feedback.
  4. Report: record anonymous scores, feedback, and facilitator guide before/after change.

03 · Concept simulation · Not professional experience

Datacenter Operations Training Lab

Incident INC-SIM-001: a server is unreachable and its network port shows a link warning. This simulation asks a learner to separate observations from assumptions, document checks, select an escalation owner and define closure evidence.

StepSimulated operational decision
ObserveCapture alert, time and affected services.
TriageCheck monitoring scope, approved port state, server power and management status.
EscalateNetwork, compute or facilities team by fault domain.
CloseAuthorized repair, stable service checks, owner acknowledgment and record.

04 · Planned cloud exercise · Not yet deployed

Azure Infrastructure Lab

Build and verify a small VM in a clearly documented Azure region with a virtual network, subnet, network security group and managed OS disk. Capture deployment status and genuine resource usage if visible, then remove billable resources.

  1. Learn Azure components and cost management.
  2. Set a budget alert; choose and document region, VM SKU and operating system.
  3. Provision a private/restricted-access VNet, subnet, VM, NIC and disk.
  4. Verify connection and capture redacted test evidence.
  5. Separate real Cost Management usage from calculator estimates; delete all lab resources.
